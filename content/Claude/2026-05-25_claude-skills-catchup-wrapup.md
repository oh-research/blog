> [!abstract] 한 줄 요약
> 연구를 새 세션에서 이어갈 때마다 "지난번에 어디까지 했지"를 매번 설명하는 불편함과 끝낼 때 진행 내용을 기록하는 귀찮음을 Claude Code 스킬 두 개(`catchup`, `wrapup`)로 자동화한 기록입니다.

## 개요

연구를 Claude Code로 진행하다 보면 매 세션이 같은 자리에서 막힙니다.

세션은 시작할 때마다 빈 상태로 열립니다. 그래서 "이 프로젝트는 무엇이고, 지난번에 무엇을 했고, 어디서부터 이어가면 되는지"를 매번 손으로 설명하게 됩니다. 문서와 코드가 쌓일수록 이 설명이 길어지고 빼먹는 것도 생깁니다.

반대로 작업을 끝낼 때는 "오늘 무엇을 했는지" 기록을 자꾸 깜빡합니다. 다음에 다시 열면 또 기억을 더듬어야 하니 악순환입니다.

이 두 가지 불편함을 스킬 두 개로 묶었습니다.

- **`catchup`** — 세션 시작 시 현재 상황을 파악하고 어디서부터 이어갈지 정리
- **`wrapup`** — 세션 종료 시 한 일을 정리해 상태 파일에 기록

그리고 진행 상황은 프로젝트마다 두는 `_Project.md` 파일 하나에 모아 둡니다. 이 파일이 두 스킬을 잇는 단일 기준점이 됩니다.

`_Project.md`는 거창할 필요가 없습니다. 다음 정도의 골격이면 충분합니다. `catchup`은 여기서 현재 상황과 TODO를 읽고 `wrapup`은 '현재 상황'을 갱신한 뒤 파일 끝에 날짜별 기록을 덧붙입니다.

```markdown
# _Project.md

## 현재 상황
- 지금 무엇을 하고 있는지 1~3줄

## TODO
- [ ] 다음에 할 일
- [ ] 미해결 질문

## 2026-05-25 — 오늘 한 일 한 줄 요약
```

> [!note] 전제
> 이 글은 연구 폴더를 git으로 공유하지 않는 환경을 기준으로 합니다. 그래서 변경 추적은 git 대신 `_Project.md`와 파일 수정 시각으로 처리합니다. git을 쓴다면 `git log`·`git status`를 더해도 좋습니다.

## 스킬이란

Claude Code의 스킬은 `.claude/skills/<이름>/SKILL.md` 형식의 마크다운 파일입니다. 파일 안에 적은 내용이 그대로 "할 일 프롬프트"가 됩니다. 이 형식은 `/이름`으로 직접 호출할 수도 있고 Claude가 상황을 보고 알아서 발동시킬 수도 있습니다.

쉽게 말하면 **매번 똑같이 치던 긴 프롬프트를 파일 하나로 저장해 두고 짧은 명령으로 부르는 것**입니다. 반복되는 루틴이 있으면 스킬로 만들기 좋습니다.

## 설치 방법

### 1. 폴더 만들기

프로젝트 루트에서 스킬 폴더를 만듭니다.

```bash
mkdir -p .claude/skills/catchup
mkdir -p .claude/skills/wrapup
```

최종 구조는 다음과 같습니다.

```
.claude/
└── skills/
    ├── catchup/
    │   └── SKILL.md
    └── wrapup/
        └── SKILL.md
```

### 2. `catchup` 스킬 작성

`.claude/skills/catchup/SKILL.md` 파일을 만들고 아래 내용을 붙여 넣습니다.

```markdown
---
name: catchup
description: 연구 세션 이어가기 — _Project.md로 현재 상황을 파악하고, 지난 작업을 요약하고, 다음 단계를 제안한다. 세션 시작 시 또는 "어디까지 했지" 같은 질문에 사용.
---

# 연구 세션 이어가기

아래를 순서대로 수행한 뒤, 멈추고 사용자 확인을 기다린다.

## 1. 현재 상황 파악 (최우선)
- 먼저 _Project.md를 읽어 프로젝트의 현재 상황을 파악한다. 이 파일을 상태의 단일 기준으로 삼는다.
- 폴더 구조를 보여주고 핵심 작업 파일을 식별한다.

## 2. 최근 작업 대조
- 최근 7일 내 수정된 파일을 나열한다 (수정 시각 기준).
- 가장 최근에 수정된 파일이 _Project.md에 적힌 현재 작업과 일치하는지 확인한다.
- 적어둔 상황과 실제 최근 수정 파일이 어긋나면 그 차이를 짚어준다.

## 3. 지난 작업 복원
- _Project.md 기준으로 최근 수정 파일들을 읽고, 완료 / 진행 중 / 막힘 으로 3~5줄 요약한다.
- TODO 마커와 미해결 질문을 수집한다.

## 4. 다음 단계 제안
- 구체적인 다음 작업 하나를 짧은 근거와 함께 추천한다.
- 작업을 시작하기 전에 사용자에게 확인 또는 방향 수정을 요청한다.

## 가드레일
- 원본 데이터를 수정하거나 삭제하지 않는다.
- 오래 걸리는 실험은 확인 없이 재실행하지 않는다.
- CLAUDE.md가 있으면 거기 적힌 프로젝트 규칙을 따른다.
```

### 3. `wrapup` 스킬 작성

`.claude/skills/wrapup/SKILL.md` 파일을 만들고 아래 내용을 붙여 넣습니다.

```markdown
---
name: wrapup
description: 연구 세션 마무리 — 이번 세션에 한 작업을 정리해 _Project.md에 반영한다. "마무리하자", "오늘은 여기까지" 같은 종료 신호에 사용.
---

# 연구 세션 마무리

아래를 순서대로 수행한다. _Project.md를 저장하기 전에 갱신안을 보여주고 사용자 확인을 받는다.

## 1. 이번 세션 정리
- 이번 세션에 한 작업을 완료 / 진행 중 / 막힘 으로 3~5줄 요약한다.
- 새로 생긴 미해결 질문이나 결정 사항을 정리한다.
- 다음 세션에서 이어갈 구체적 다음 단계를 1~3개 적는다.

## 2. _Project.md 갱신안 작성
- 먼저 기존 _Project.md를 읽어 구조와 형식을 파악한다.
- 그 구조를 유지한 채 '현재 상황' 부분을 위 요약으로 갱신한다.
- 파일 끝에 날짜가 붙은 짧은 작업 기록 한 줄을 덧붙인다. 예) "## 2026-05-25 — (한 줄 요약)"

## 3. 확인 후 반영
- 변경 전/후 차이를 사용자에게 보여준다.
- 확인을 받은 뒤에만 _Project.md를 저장한다.

## 가드레일
- 기존 _Project.md 내용을 함부로 삭제하지 않는다. 갱신은 해당 섹션만.
- 확인 없이 덮어쓰지 않는다.
```

> [!tip] `name`과 명령·경로는 영어로
> 설명 문장은 한글로 써도 똑같이 동작합니다. 다만 `name`(슬래시 명령 이름이 됩니다)과 본문 속 파일 경로·명령어(`_Project.md`, `mkdir` 등)는 식별자·명령이라 영어로 두는 것이 좋습니다.

### 4. 인식 확인

새 세션을 열고 스킬이 등록됐는지 확인합니다.

```
/catchup
```

자동완성에 뜨거나 실행되면 설치는 끝입니다.

## 사용법

### 시작할 때 — `/catchup`

세션을 열고 `/catchup`을 치면 Claude가 `_Project.md`부터 읽습니다. 이어서 최근 수정 파일과 대조해 완료·진행 중·막힘으로 요약하고 다음 단계를 제안한 뒤 멈춥니다. 사용자 확인을 받고 나서 작업을 시작합니다.

직접 명령을 치지 않아도 "어디까지 했지?"처럼 말하면 description을 보고 Claude가 알아서 발동하기도 합니다.

### 끝낼 때 — `/wrapup`

작업을 마무리할 때 `/wrapup`을 치면 이번 세션에 한 일을 정리해 `_Project.md` 갱신안을 보여줍니다. 차이를 확인하고 승인하면 그때 저장합니다. "오늘은 여기까지" 같은 종료 신호로도 발동합니다.

> [!info] 두 스킬은 한 쌍
> 시작은 `catchup`, 마무리는 `wrapup`입니다. 이 루프가 돌면 `_Project.md`가 항상 최신으로 유지되어 git 없이도 진행 기록이 끊기지 않습니다.

## 정리

핵심은 단순합니다. **반복하는 일은 파일로 저장해 두고 짧게 부르는 것**입니다.

- `_Project.md` 하나로 진행 상황을 모읍니다.
- `catchup`으로 이어받고 `wrapup`으로 기록합니다.

이 세팅 이후로는 "지난번에 어디까지 했더라"를 설명하는 시간이 거의 사라졌습니다. 연구처럼 긴 호흡으로 이어가는 작업일수록 효과가 큽니다.

스킬은 한 번 만들고 끝나지 않습니다. 쓰다 보면 빼거나 더할 단계가 생깁니다. 그때 SKILL.md를 고치면 내 작업 방식에 맞게 다듬어집니다.
